# ヴァンパイア・ハウス — ルール確定版

企画書（`docs/concept.md`）に残されていた「未決定事項」を、実装とバランス調整を通して
すべて確定させたもの。数値の根拠は末尾のシミュレーション結果に基づく。

---

## 0. 盤面はルールそのものを描いた図形

以前は、渡してもらった盤面写真をそのまま背景に敷き、写真とのズレを画面上で
人力ドラッグして合わせる「盤面調整モード」を用意していた。写真という
**先に確定した見た目**に当たり判定を後から合わせようとした結果、
本来ルールから機械的に決まるはずの座標（同心円の半径・8等分の角度）を
毎回目視調整する羽目になり、やることが逆だった。

正しい順序は、①ルール（§1）を満たす盤面をシンプルな幾何図形として実装し、
②デジタルでテストプレイと調整を重ねてルールを確定させ、③**最後に**、
その時点で確定している当たり判定に合わせてデザイン画像を背景として敷く、
という順番のはずだった。③はまだやっていない。今の盤面は①②の状態、
すなわち**写真を使わない、ルールに沿った図形そのもの**（`src/ui/geometry.ts` が
座標計算、`src/ui/board-view.ts` がその描画とクリック判定を行う）。

座標はすべて定数として決め打ちしてある（`RING_RADII`・`CASTLE_DISTANCE`・
`SECTOR_ANGLE`）。同心円4本を等間隔に、8方向を等角度に置くだけなので、
写真とのすり合わせや `localStorage` への保存は不要になった。
当たり判定はマス中心を囲む円（半径はリング幅と弧の長さから自動計算）。

| 位置と記号（盤面図形が表すもの） | ルールとして実装したもの |
| --- | --- |
| 中心の赤い円（村） | ここで**血を1個獲得**できる、という規則 |
| 四隅の菱形（城） | それが**プレイヤーの拠点**で、**持ち帰るまで得点にならない**という規則 |
| 緑の扇形（洞窟） | 触れると**コウモリを1枚引ける**、同じ洞窟は**1夜1回**という制限 |
| 金の三角×2（ハンター） | **1ラウンドに1マスずつ周回する**という運動法則、触れたら即死という規則 |
| （時間の概念なし） | **4ラウンドで夜明け**、**4夜で終了**、**最終夜は得点2倍**という時間設計 |
| （移動の概念なし） | **1ターン3歩**、**血を2個持つごとに1歩遅くなる**という移動規則 |

ハンターの数は2体。3体にする案も試したが、ボット対戦で明らかにバランスを
崩したため不採用にした（§5・§9）。

デザイン画像（`src/assets/board.png`）は破棄していないが、現時点では
どこからも参照していない。使うなら、今の当たり判定（座標定数）を動かさずに、
その座標へ絵のほうを合わせ込む形で背景に敷く。

## 1. 盤面

同心円4リング＋放射線8本。すべてのリングが8マスに分割されているので、
放射方向の接続は 1:1 で素直に対応する。

| 位置 | マス数 | 内容 |
| --- | --- | --- |
| 中心（リング0） | 1 | **村**。血の唯一の供給源。8方向すべてのリング1マスと繋がるハブ |
| リング1〜4 | 各8 | 通常の移動路 |
| リング4の外側 | 4 | **城**。四隅（斜め方向のセクター1・3・5・7）にぶら下がる |

- **洞窟（緑）**: リング3のセクター0・2・4・6。城の直通ルートから横に1歩ずれた位置。写真にそのまま描かれている
- **日陰（水色）**: リング4のセクター0・2・4・6（外周の避難所）＋ リング2の同セクター（深部の命綱）の計8マス。
  写真には色分けされた形では描かれていないため、画面上では固定の装飾を足さず、
  夜明け直前に「そこにいると焼かれる／焼かれない」を半透明の警告色で示すだけにしてある
- 城 → 村は最短5歩。往復10歩

```
        城              城
          \            /
           +--------- 外周リング4（日陰4）
            +-------- リング3（洞窟4）
             +------- リング2（日陰4・ハンター巡回）
              +------ リング1
               (村)
```

## 2. 確定した未決定事項

| 項目 | 確定内容 | 理由 |
| --- | --- | --- |
| 移動手段 | **固定歩数**。基礎移動力3 | 移動にダイスを入れると「予測可能な脅威／判断で死ぬゲーム」という設計原則が崩れる。ダイスは移動ではなく収入に置いた（§7） |
| 血の重さ | **血2つごとに移動力−1**（最低1） | 「欲張るほど帰りが遠い」を盤面の距離ではなく速度でも表現する |
| 日陰の数と配置 | **8マス固定・定員1人** | 数を絞って椅子取りにするより、深部4マスをハンターの巡回リング上に重ねる方が緊張が持続する |
| 日陰に隠れるコスト | **なし** | 寄り道そのものが既にコスト。二重に取ると引き際の判断が単純に「帰る」へ寄る |
| 村の血の総量 | **有限。プレイヤー数 × 5** | 枯渇は保険としての終了条件。通常はラウンド数で決着する |
| ゲーム終了条件 | **4夜（16ラウンド）経過**。村の血が尽き、誰も運搬していない場合は即終了 | 企画書の「4ターン周期の太陽」をそのまま夜の単位にした |
| 逆転要素 | **最終夜の持ち帰りは2点** | 最終夜だけリスクの見返りが倍になり、差がついていても勝負が残る |
| コウモリの種類と枚数 | 5種20枚（下記） | 移動補助を厚く、直接妨害を薄く |
| 毎ラウンドのランダム性 | **月潮**。2d4で「血脈が湧くリング」が決まる（§7） | カタンのダイスに相当する、全員が毎ラウンド同時に受ける賭け |
| 終盤に向けた強化 | **眷属**。コウモリを対価に雇う永続強化、1夜1体（§8） | 出目の当たり外れを、夜を重ねるごとに技術で均していくための軸 |

## 3. ターンの流れ

1. 手番プレイヤーの移動力が `max(1, 3 − floor(運搬中の血 ÷ 2))` に設定される
   （ターン開始時に確定。ターン中に血が増減しても変わらない）
2. 隣接マスへ1歩ずつ移動する。コウモリは1ターンに2枚まで、任意のタイミングで使える
3. ターン終了時、村にいれば血を1つ得る
4. 全員の手番が終わると **ハンターが1マスずつ進む**（踏まれた者は死亡）
5. 続けて **月潮**（2d4）が振られ、指されたリングに立つ者が血を吸う（§7）
6. 4ラウンド目の終わりに **夜明け** が来る

## 4. 太陽（夜明け）

企画書の「4ターン経過後に太陽が来る」を、**4ラウンド＝1夜** として実装した。
夜明けの瞬間、日陰マスまたは城にいないヴァンパイアは全員焼かれる。

- 焼かれた者は運搬中の血をすべて失い、自分の城へ戻される
- 失われた血は**村へ還る**（消滅させると盤面から資源が痩せ、終盤が停滞するため）
- 手札のコウモリは失わない
- 村・洞窟は安全ではない
- 夜明けまでの残りラウンド数は常に画面に表示される。運の要素は一切ない

## 5. ハンター

**2体**。リング2を、盤面の反対側同士を保ったまま同じ向きに1ラウンド1マスで周回する。

- 同じマスに入る／入られると即死（運搬中の血は村へ還る）
- 位置も進路も完全に公開情報。盤面には次の一歩が半透明の三角形で予告される
- リング2は村へ向かうときに必ず横切るリングなので、往復のたびに計算が要る
- 深部の日陰（リング2）はこの巡回路の上にある ＝ **命綱と死の罠が同じマス**

> 3人以上でハンターを3体にする案は、リング1・3・4のいずれに置いても
> 1ゲームあたりの死亡数が跳ね上がり無得点プレイヤーが増えたため不採用（§9）。

## 6. コウモリ（発展カード）

洞窟マスに入ると1枚引ける。同じ洞窟は一夜に1回、1ターンに引けるのは1枚まで
（夜明けですべての洞窟が復活する）。手札は伏せたまま持つ。

| カード | 枚数 | 効果 |
| --- | --- | --- |
| 疾走 | 6 | このターンの移動力 +2 |
| 誘導 | 4 | ハンター1体を隣のマスへ1歩動かす。踏まれたヴァンパイアは死ぬ |
| 影紡ぎ | 4 | 今いるマスを今夜だけ日陰にする（夜明けで消滅） |
| 強奪 | 3 | 城の外にいる他プレイヤー1人から血を1つ奪う |
| 飛翔 | 3 | 空いている日陰マスへワープする。移動は終了。ハンターの上に降りれば死ぬ |

山札が尽きたら捨札を切り直す。

## 7. 月潮 ―― 全員が毎ラウンド受けるダイス

カタンに倣うなら、このゲームには2つ足りないものがあった。
**全プレイヤーが毎ターン受けるランダム性**と、**終盤に向けてそれを均していく技術**である。
月潮（§7）と眷属（§8）は、その2つをこのゲームの形に合わせて入れたもの。

### どこにダイスを置くか

§2 で「移動にダイスを入れると設計原則が崩れる」と書いたのは今も正しい。
崩れるのは **死因がランダムになる** からで、ダイスそのものが悪いわけではない。

カタンのダイスも、プレイヤーを殺しはしない。決めるのは**産出**だけで、
盗賊をどこに置くかは人間が決める。つまり **運は収入に、判断は生死に**、と
役割が分かれている。同じ切り分けをこのゲームに持ち込んだ:

- **太陽とハンターは完全に決定論のまま**。夜明けまでの残りラウンドも、
  ハンターの次の一歩も、これまでどおり盤面に全部書いてある。
  死ぬのは今も計算違いのときだけ
- **ダイスが決めるのは、稼げたかどうかだけ**

（テスト `死因はダイスに触れない` が、シードを変えても死亡数が
1つも変わらないことを実際に確認している。）

### ルール

各ラウンドの終わり、全員の手番が済み、ハンターが動いたあとに **2d4** を振る。
出目の合計（2〜8）が、その瞬間に血脈が湧くリングを指す。

**リング = |出目 − 5| + 1**

| 出目 | 湧くリング | 確率 |
| --- | --- | --- |
| 5 | リング1 | 25.0% |
| 4・6 | リング2 | 37.5% |
| 3・7 | リング3 | 25.0% |
| 2・8 | リング4 | 12.5% |

指されたリングに立っているヴァンパイアは全員、村の血から1つ吸い上げる。
**村（リング0）と城は血脈の外**。村はもともと血の出どころで、城は避難所だから。

### なぜこの形なのか

- **振るのはターンの後**。だから足を止める場所を選ぶ時点では出目が分からない。
  「どのリングで夜を過ごすか」がそのまま賭けになる。カタンで開拓地を置く場所を
  先に決めてからダイスを振るのと同じ順序
- **確率は常に公開**。盤面の放射線の上に、リングごとの濃さが刻んである。
  読めないのは出目だけで、勝率は最初から全員に見えている
- **最も濃いリング2は、ハンターの巡回路**。いちばん儲かる場所がいちばん危ない。
  同心円がもともと持っていた「深いほど危なく、遠い」という傾きに、
  収入の傾きが重なる
- **全員が同時に受ける**。他人の手番でも盤面から目を離せなくなる

血脈からの収入は、実測で盤上の血のおよそ **4割** を占める（残りは村）。
村へ通う往復が主、月潮はその道中で拾うもの、という比率になっている。

## 8. 眷属 ―― 出目を均していく技術

自分の城にいるとき、**コウモリを対価に**永続の強化を雇える。**1夜に1体まで**、
同じ眷属は1体まで。4夜のうちに揃うのはせいぜい3体なので、
どれを先に連れてくるかが技術になる。

| 眷属 | 対価 | 効果 |
| --- | --- | --- |
| 🦇 群れ | コウモリ1 | 月潮が**隣のリング**を指したときも血を得る（当たり幅が3リングに広がる） |
| 🦷 牙 | コウモリ1 | 月潮が自分のリング**ちょうど**を指したとき、血を**2つ**得る |
| 🏺 器 | コウモリ1 | 血の重さによる減速を **−1 まで**しか受けない |
| 🪽 翼 | コウモリ1 | 基礎移動力 **+1** |

**群れ**が当たり幅を広げ（分散投資）、**牙**が当たりの取り分を厚くする（都市への昇格）。
カタンで「番号を散らして置く」のと「都市に建て替える」のに対応する2軸で、
どちらも月潮の当たり外れを均す方向に働く。

### なぜ血ではなくコウモリで払うのか

最初は「持ち帰った血を対価にする」形で作った。これは**測ってみて没にした**。

このゲームは1人が1ゲームで城へ運び込める血がせいぜい5〜8しかない。
血は得点そのものなので、血で強化を買うと「払った点を強化が取り返せるか」という
勝負になり、どう値付けしても取り返せなかった。ボット同士の総当たりで、
血で買う版は**雇った側が必ず負けた**（席0の勝率 80.9% → 45〜77%）。

カタンで資源と勝利点が別の通貨になっているのは、たぶんこのためで、
同じ理屈でコウモリ（得点にならない資源）を対価に切り替えた。
払うのは点ではなく、**洞窟へ寄り道する手数**と、
**夜明けに自分を救ったはずの1枚**になる。

### 効き目の実測

眷属を最初から配った席0が、素の相手に勝つ割合（2人戦・600戦）:

| 持っている眷属 | 勝率 |
| --- | --- |
| なし | 80.9% |
| 翼 | 85.3% |
| 器 | 81.1% |
| 群れ | 85.5% |
| 牙 | 89.8% |
| 群れ＋牙 | 92.8% |
| 4体すべて | 94.8% |

単体でもマイナスにならず、組み合わせるほど伸びる。揃えきっても勝ちは確定しない。
実戦（自力で雇う）でも、雇う側の勝率が上がることを確認してある。

### 検討して没にした案

| 案 | 測った結果 |
| --- | --- |
| 血を対価にする | 雇った側が必ず負ける。1ゲームの総得点に対して高すぎる（上記） |
| 対価をコウモリ2枚にする | コウモリ1枚の価値（勝率 +2.4pt 相当）に対して割高で、やはり負ける |
| ボットが血脈の上に居座って月潮を待つ | 村への往復に常に負けた。村は「立っていれば毎ターン確実に1つ」、血脈は最良でも1ラウンド1つ弱。月潮は狙って待つものではなく、行き帰りに拾うもの |
| 牙を「群れで広げた外周ぶんも倍」にする | 2つ揃えた者の勝率が 99.8% に達して手が付けられなくなった。倍になるのはちょうどのリングだけに限定 |
| 眷属を1夜に何体でも | 大きな1回の持ち帰りで一気に揃ってしまい、夜を重ねる意味が消えた |

## 9. バランス（ボット60戦 × 各人数）

`npm run balance` で再現できる。すべてボットの自動対戦。

| 人数 | 平均得点 | 最高 | 最低 | 1ゲームの死亡数 | 勝差 | 村の残り血 | 1人あたり眷属 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 2人 | 7.44 | 19 | 1 | 0.42 | 3.15 | 7.07 / 18 | 1.77 |
| 3人 | 7.21 | 19 | 0 | 1.22 | 3.10 | 11.27 / 27 | 1.32 |
| 4人 | 6.45 | 17 | 1 | 2.23 | 2.60 | 17.03 / 36 | 1.15 |

村の血の総量はプレイヤー数 × 9 に増やした（月潮という2つ目の収入源が増えたぶん）。
使い残しの割合（39〜47%）は月潮を入れる前とほぼ同じで、枯渇は今も保険としての終了条件。

狙った形になっている点:

- **1夜1往復が基準線**。城→村5歩、村→城5歩、1夜に使えるのは12歩。
  ハンターを避けて回り道すると、それだけで予定が崩れる
- **月潮を入れて死亡数が下がった**（4人戦で 3.95 → 2.23）。村まで踏み込まなくても
  帰り道で血が拾えるようになったぶん、無理をする必要が減っている
- **村に居座って2つ目を吸うと移動力が2に落ちる**。城までは戻れないが、
  リング2の深部日陰までなら2歩で届く ―― ただしそこはハンターの巡回路
- 死亡数は人数とともに増えるが、無得点で終わるプレイヤーはほぼ出ない

### 検討して不採用にした案

| 案 | 結果 |
| --- | --- |
| 3人以上でハンター3体（リング4） | 帰り道を塞ぎすぎる。4人戦の死亡数 5.9、無得点 1.03/game |
| 同（リング3） | さらに悪化。死亡数 6.25、平均得点 2.09 |
| 同（リング1） | 村の周りが詰まり無得点 0.48/game |
| 日陰を人数依存（2人=4マス） | 2人戦で深部の避難所が消え、「2つ目を吸う」選択肢そのものが消滅 |

### 残っている課題: 手番順の有利

ボット同士の対戦だと、**先手が勝ちすぎる**。2人戦で席0の勝率が 73%（400戦）。

これは月潮・眷属を入れる前から在る性質で、むしろ少し緩和されている
（同じ計測で、入れる前は 87.3%）。同じ思考ルーチンのボット同士だと、
先に動いたぶんだけ村の血にも日陰にも先に手が届くのが効いているらしい。
未着手。直すなら、手番順に応じた初期配布か、夜ごとの手番ローテーションあたり。

## 10. 実装の構成

```
src/game/     ルール本体（DOM 非依存・全テスト対象）
  board.ts    盤面の生成、隣接、最短経路
  rules.ts    状態遷移。すべての公開関数は state を破壊的に更新する
  bats.ts     コウモリの定義と山札
  thralls.ts  眷属（永続強化）の定義と対価
  ai.ts       ボット。危険マスを避けて経路を引き、夜明けから逆算して引き際を決める。
              予定を1ターンも遅らせない範囲で、月潮の濃いリングに足を止める
  rng.ts      シード固定の PRNG（同じシード＝同じ展開）
src/assets/
  board.png     提供されたデザイン画像。現状どこからも参照していない
src/ui/
  geometry.ts     ルールから決まる座標定数（リング半径・角度）と、
                  各マスの中心座標・当たり判定半径の計算
  board-view.ts   同心円と扇形をそのまま描画し、円の当たり判定を重ねる
scripts/      バランス検証用のシミュレーション
```
